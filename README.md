# AI Team Workbench · AI 团队工作台

**一个可自部署的 AI 团队工作台。从群里派工，到独立执行，再到按版本验收。**

在项目群里发一条任务，总管会按需召集研究员、工程师和审核员。每个成员用自己的会话接手工作。你可以在任务卡里追踪谁在处理、用过哪些依据、哪一版报告通过了复核。

[下载完整源码 ai-team-workbench-source.zip](./ai-team-workbench-source.zip?raw=1)

## 能做什么

- **团队角色与记忆。** 内置四个角色。总管协调任务，研究员核对资料，工程师分析并出稿，审核员独立复核。成员各自保留 DeepSeek Harness 会话和角色记忆。你可以查看、补充和更正角色记忆，系统保留更正原因和历史版本。
- **项目群聊与公开交接。** 你在群里提出目标或追问。成员用 `@` 交接，接手的成员在自己的会话里执行，再把结果和下一步发回同一个群。简单任务可以由总管直接处理。
- **只读资料与工具凭据。** 成员通过专用工具读取项目资料、做计算或检查表格。实际读取、计算和交付结果都有凭据，报告和审核可以引用这些凭据或已有群聊消息。原始资料保持只读，报告另存为可下载的 Markdown 文件。
- **版本审核与修订。** 初稿由负责的成员保存，审核员须打开指定版本，再登记通过或要求修改，附上核对依据。修订稿可以关联旧稿，审核员按新版复核。工作台显示待正式审核、要求修改或通过等状态。
- **任务进度、异常与续办。** 「任务梳理」根据实际记录展示原始指令、成员分工、工具结果和交付物。可以展开群聊查看交接细节，也可以在「报错与提醒」定位出错成员和工具。失败、中断或待审核的任务可以发起关联的后续轮次，已有记录和产出都可追溯。
- **多项目与导出。** 每个项目分别保存会话、记忆、群聊、资料和产出。浏览器里可以切换项目，也可以导出项目讨论记录和报告，方便留档。

## 试一次团队复核

下面的例子可以检验交接有没有推进工作，以及审核员能否发现原稿的问题。启动工作台后，新建项目并上传源码包里的 `examples/review-sample.csv`。这是一份合成数据。

> 请工程师保存一份初稿，暂写「T2 平均值为 48，测量日期完整」。请审核员打开初稿和原表，独立复算均值并检查日期，登记审核结论。有误就指出位置，让工程师另存修订版，再复核新版。

三条 T2 记录的平均值是 **44**，编号 `S03` 的日期为空。用「任务梳理」对照工程师的初稿、审核员的复算结果和最终审核记录，可以看到哪里被指出、谁改了什么，以及最终审的是哪一版。

## 当前版本

- **部署与访问。** 工作台是运行在 Linux 电脑或服务器上的单用户网页应用，通过口令访问。源码包包含 Node.js 服务、网页、安装脚本、测试和 DSH 协作插件。
- **运行方式。** 从网页手动发起任务。任务全局排队，单轮上限五分钟，模型请求串行。定时联网检索和消息推送需要另接自动化。
- **模型与资料。** 使用 DeepSeek API Key，运行固定版本的 DeepSeek Harness `0.2.2-rc.4`。可上传 TXT、Markdown、CSV、TSV、JSON 和 LOG，单文件最多 8 MB。记录和文件保存在部署机器上，模型推理所需的上下文会发送到 DeepSeek API。

详细部署与复现说明见解压后的 `ai-team-workbench/README.md`。

## 运行

需要 Linux、Node.js 24.9 或更新版本、npm、GNU coreutils 和 unzip。下载源码包后运行：

```bash
unzip ai-team-workbench-source.zip
cd ai-team-workbench
npm ci --ignore-scripts
npm run setup
npm start
```

首次配置请在终端设置网页口令并输入自己的 DeepSeek API Key，然后打开 `http://127.0.0.1:3358`。使用远程服务器时，可按源码包 README 建立 SSH 转发。需要常驻运行时，可以按 README 安装 systemd 用户服务。
